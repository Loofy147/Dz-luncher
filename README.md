# Dz-luncher — سوق التحقق من الأفكار والاستبيانات في الجزائر

منصة عربية باتجاه RTL تساعد أصحاب المشاريع على اختبار افتراضاتهم قبل الإطلاق، وتتيح للمشاركين الإجابة عن الاستبيانات واختبار المنتجات مقابل مكافآت معلنة. هذا المستودع يحتوي على شريحة MVP فعلية، لا مجرد صفحات تصميمية.

> **الحالة:** نسخة تجريبية قابلة للتشغيل والاختبار. ليست جاهزة للإطلاق التجاري أو لاستقبال بيانات شخصية حقيقية حتى تُستكمل بوابات الخصوصية والأمن والتشغيل الموضحة أدناه.

## بوابات ما قبل الإطلاق

**لا تجمع بيانات شخصية حقيقية ولا تفعّل تحصيل الأموال/المكافآت الحقيقية بعد.** قبل التجربة الميدانية، اتبع [خطة الإغلاق قبل الإطلاق ومصادرها](docs/GO_LIVE_REMEDIATION_PLAN.md)، وراجع [متطلبات الخصوصية والأمن والامتثال](docs/PRIVACY_SECURITY_COMPLIANCE.md) و[خطة التجربة وقياس النتائج](docs/PILOT_RESEARCH_PLAN.md). الإطلاق مشروط بحسم الالتزامات القانونية ومكان البيانات، والتحقق من مزوّد الاستضافة والدفع، واجتياز اختبارات PostgreSQL والاستعادة والأمن.

## الموجود الآن

- واجهة عربية متجاوبة واتجاه RTL.
- إنشاء حساب ودخول، مع جلسات مخزّنة في قاعدة البيانات ورمز CSRF.
- إنشاء استبيانات ومسودات ونشر نسخة ثابتة منها.
- أنواع أسئلة اختيار واحد، ومقياس، وعدد، ونص؛ مع شروط إظهار وأسئلة تأهيل قد تنهي المشاركة.
- التحقق من الإجابات، ومؤشرات جودة مع مراجعة بشرية، وحدود حصص.
- تقارير تُظهر تدفق العينة والقيود، وتبقي الاستجابات المصرّح بها منفصلة عن إثبات الطلب الفعلي.
- دفتر مكافآت بمعاملات وقيود تكرار، وتمويل وتسجيل تسوية يدوية بعد التحقق الخارجي.
- تصدير تحليلي مستعار لا يضم النصوص الحرة افتراضياً.
- SQLite للتطوير المحلي، وPostgreSQL للنشر، وAlembic migrations، واختبارات CI.

## التشغيل المحلي

المتطلبات: Python 3.12 أو أحدث.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
cp .env.example .env
uvicorn app.main:app --reload --env-file .env
```

افتح <http://127.0.0.1:8000>. سجّل حساباً بدور «صاحب مشروع» لإنشاء الاستبيانات، أو دور «مشارك» للإجابة. تُحمّل الواجهة المسودة الابتدائية كقالب مساعد فقط؛ استبدلها بأسئلة مشروعك الفعلية قبل النشر.

تُنشأ قاعدة بيانات SQLite محلياً في `.data/dz_luncher.db`. عند نشر التطبيق، تُدار الجداول عبر Alembic لا عبر `create_all`:

```bash
alembic upgrade head
```

## الاختبارات والفحوص

```bash
python -m pytest -q
ruff check app tests scripts validation_core.py
python -m compileall -q app scripts validation_core.py
```

الاختبارات تستخدم بيانات اصطناعية وقاعدة بيانات مؤقتة؛ لا تمثل اختباراً لمشاركين حقيقيين أو جودة كشف احتيال في الجزائر. راجع `docs/VALIDATION_ENGINE_IMPLEMENTATION.md` و`docs/TEST_PLAN_AND_ACCEPTANCE.md`.

## المكافآت: تشغيل يدوي آمن نسبياً

لا يوجد مزوّد دفع متكامل بعد. الأوامر التالية **تسجل** معاملات تحقّق منها مشغّل بشري؛ لا تحوّل الأموال ولا تثبت صحتها من تلقاء نفسها.

```bash
# أظهر الاستحقاقات التي ما زالت تنتظر التسوية
python -m scripts.manage_rewards pending

# استخدم فقط بعد استلام أموال الحملة والتحقق منها خارج النظام
python -m scripts.manage_rewards fund \
  --survey <campaign-slug> --amount-dzd 5000 \
  --reference <verified-receipt-reference> \
  --idempotency-key <unique-stable-key> --operator <operator-name-or-role>

# استخدم فقط بعد إتمام الدفع للمشارك والتحقق من إثباته خارج النظام
python -m scripts.manage_rewards mark-paid \
  --obligation <obligation-id> --reference <external-transfer-reference> \
  --operator <operator-name-or-role>
```

قبل نشر حملة بمكافآت، يشترط النظام تسجيل تمويل مؤكد يغطي الحد الأقصى `المكافأة × عدد المشاركات`. لا تدخل مراجع وهمية ولا تعتبر تسجيل العملية تأكيداً على استلام الأموال أو دفعها.

## تشغيل محلي عبر Docker Compose

```bash
export POSTGRES_PASSWORD="ضع-كلمة-مرور-عشوائية-محلية-قوية-هنا"
export SESSION_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
export PSEUDONYM_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
# SESSION_SECRET وPSEUDONYM_SECRET يجب أن يكونا مختلفين
# حمّل .env بهذه القيم أو صدّرها في الطرفية قبل التشغيل
 docker compose up --build
```

الخدمة تستخدم PostgreSQL عندما تعمل في وضع `APP_ENV=production`. لا تنشر كلمة مرور Compose الافتراضية، ولا ترفع ملف `.env` أو أسراراً إلى Git.

## بنية المشروع

```text
app/                     تطبيق FastAPI والخدمات والنماذج
app/templates/           قوالب HTML العربية واتجاه RTL
app/static/              CSS وJavaScript
validation_core.py       عقد الاستبيان والتحقق والجودة والتقارير
scripts/manage_rewards.py أوامر المشغّل لتسوية الدفتر
alembic/versions/        ترحيلات قاعدة البيانات
 tests/                  اختبارات النواة والخدمات والتكامل
 docs/                   وثائق المنتج والبحث والهندسة والخصوصية
.github/workflows/ci.yml فحوص CI
```

## حواجز ما قبل الإطلاق العام

- مراجعة قانونية متخصصة في الجزائر لقانون حماية البيانات 18-07 وتعديلاته، وتحديد جهة المعالجة والأساس القانوني والإشعارات والموافقات وحقوق أصحاب البيانات.
- التحقق من موقع الاستضافة والمعالجين الفرعيين والنقل عبر الحدود والاحتفاظ والحذف قبل جمع أي بيانات إنتاجية.
- إثبات عنوان البريد واستعادة كلمة المرور، وحدود طلبات ومكافحة إساءة الاستخدام وتكوين الوكيل الموثوق وTLS.
- سياسة تظلّم ومراجعة بشرية ووضوح شروط المكافآت، ثم تكامل صرف فعلي أو عملية تشغيلية مُدققة.
- اختبار اختراق ومراجعة اعتماديات واختبار تحميل، ونسخ احتياطي مع تجربة استعادة.
- مراجعة الحصص تحت PostgreSQL ومعاملات الإنتاج ومراقبة الدفتر المالي قبل فتح الحملات المدفوعة.

تفاصيل النطاق والافتراضات والاختبارات المفتوحة في `docs/`، وقرارات التصميم في `docs/decisions/`.
